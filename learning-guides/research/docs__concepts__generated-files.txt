Files it edits (marker injection)

Rather than overwrite shared files, Grit injects at // grit:* markers. Keep the markers in place — they're how generation and seeding stay idempotent.

Routes are the exception, and used to be the worst case: four edits per resource, hundreds of lines apart, in a routes.go that passed a thousand lines with a handful of resources. Each resource now gets its own internal/routes/<resource>_routes.go holding the handler and every path that reaches it, and routes.go no longer changes when you add or remove one.

PathWhat it is

apps/api/internal/models/user.goModel registered in Models() at // grit:models

packages/shared/schemas/index.tsSchema re-exported at // grit:schemas

apps/admin/resources/index.tsResource registered at // grit:resources

Adding a route to a resourceOpen internal/routes/<resource>_routes.go and add a line. The file registers itself from an init(), so creating one mounts a resource and deleting one unmounts it; nothing else refers to it by name. m.Public is outside the auth middleware and behind an API key, m.Protected takes a JWT or an API key, and m.Admin also requires the ADMIN role. Mount is defined in internal/routes/resources.go.

Yours vs regeneratedEverything above is your code once generated — edit models, add service methods, restyle screens freely. Put custom logic in the service layer, not in packages/shared/types/*, which grit sync rewrites from your Go structs every time it runs.

Adding a field to a resource you have already editedRe-running grit generate resource writes these files again from scratch. If you have edited them, Grit compares each one against what it last wrote, stops before touching anything, and names the files at risk. Nothing is lost, but nothing is generated either.

To add a field without that, add it in place with grit generate field <Name> <name:type>, then grit migrate. It reaches the model, the handler's request structs and PATCH allow-list, the CSV importer, the types, the Zod schemas and the admin, and leaves the rest of each file as you had it. It covers scalar, select and toggle fields.

Adding the field to the model by hand and running grit sync is not enough on its own. Sync updates the types, the schemas and the admin, but the API accepts only what the handler's request structs name, so the field is shown, submitted, and dropped.

--force regenerates anyway, overwriting your edits. Commit first: there is no backup.

Escape hatchNeed to pull a resource back out? grit generate remove resource <Name> deletes exactly these files and unwinds the marker injections — a clean inverse of generation.
